═════════════════════════════════════════════════════════════════════════════════

Para n = 1000 elementos:

O(1):        1           operação

Interpretação:

🌟 PONTOS-CHAVE PARA LEMBRAR
═════════════════════════════════════════════════════════════════════════════════

1. Big-O descreve o PIOR CASO
   └─ Garante que o algoritmo nunca será pior que isso

2. O(n log n) é frequentemente o melhor que podemos fazer
   └─ Merge Sort sempre, QuickSort em média

3. Evite O(2ⁿ) a todo custo
   └─ Use programação dinâmica quando possível

4. Escolha do algoritmo importa MUITO
   └─ Fibonacci: 154ms vs <1ms (1500x diferença!)

5. Considere o tamanho da entrada
   └─ Para n pequeno, O(n²) pode ser aceitável
   └─ Para n grande, O(n log n) é necessário

6. Trade-offs são reais
   └─ Merge Sort: O(n log n) mas usa O(n) espaço
   └─ QuickSort: O(n log n) em média, O(n²) no pior caso

7. Análise é previsível
   └─ Com análise correta, você sabe como o algoritmo escala
