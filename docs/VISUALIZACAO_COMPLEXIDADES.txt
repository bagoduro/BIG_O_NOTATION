ALGORITMOS POR ORDEM DE VELOCIDADE (do mais rápido para o mais lento)
═════════════════════════════════════════════════════════════════════

1️⃣  O(1)  - Tempo Constante
    └─ Acesso direto a arrays, operações primitivas

2️⃣  O(log n) - Logarítmico
    └─ Busca Binária (Exercício 2)

3️⃣  O(n) - Linear
    ├─ Busca Linear (Exercício 1)
    ├─ Verificação de Palíndromo (Exercício 8)
    └─ Programação Dinâmica - Fibonacci (Exercício 7)

4️⃣  O(n log n) - Linearítmico
    ├─ Merge Sort (Exercício 6)
    └─ QuickSort (caso médio, Exercício 5)

5️⃣  O(n²) - Quadrático
    ├─ Bubble Sort (Exercício 3)
    ├─ Selection Sort (Exercício 4)
    └─ QuickSort (pior caso, Exercício 5)

6️⃣  O(n·m) - Produto de dois tamanhos
    └─ Busca de Padrão (Exercício 9)

7️⃣  O(V+E) - Linear em relação ao grafo
    ├─ DFS (Exercício 10)
    └─ BFS (Exercício 10)

8️⃣  O(2ⁿ) - Exponencial ❌ EVITAR!
    └─ Fibonacci Recursivo Simples (Exercício 7)

REGRA DE OURO
═════════════

Se o seu algoritmo tem:
• O(1): Perfeito! ⭐⭐⭐⭐⭐
• O(log n): Excelente! ⭐⭐⭐⭐
• O(n): Bom! ⭐⭐⭐
• O(n log n): Aceitável ⭐⭐
• O(n²): Devagar, considere otimizar ⚠
• O(2ⁿ): PROBLEMA! Use DP ou outro algoritmo ❌

DEMONSTRAÇÃO VISUAL: FIBONACCI
══════════════════════════════

Recursivo Simples vs Com Memoização

             fib(5)
            /      \
        fib(4)     fib(3)
       /      \    /     \
    fib(3)  fib(2) fib(2) fib(1)
   /    \    / \   / \
fib(2) fib(1) ... fib(0)

Vê o problema? fib(3) é calculado DUAS vezes, fib(2) TRÊS vezes!
Isso é recompilado recursivamente para cada subcálculo.

Para fib(35): 29.860.703 chamadas! 🤯

Com Memoização:
fib(0) = 0 ✓ (armazenado)
fib(1) = 1 ✓ (armazenado)
fib(2) = 1 ✓ (armazenado)
... (cada valor calculado UMA ÚNICA VEZ)
fib(35) = ? ✓ (resultado em < 1ms)

Apenas 69 chamadas! 📊

CONCLUSÃO
═════════

A análise de complexidade é FUNDAMENTAL para escolher bons algoritmos.

Diferença de desempenho:
• Fibonacci(35):    154ms vs <1ms   = 1500x mais rápido ✓
• Merge Sort vs BS: O(n log n) vs O(n²) = 100x mais rápido ✓
• Binary Search vs Linear: O(log n) vs O(n) = até 1000x mais rápido ✓

Portanto: SEMPRE analise a complexidade antes de implementar!
